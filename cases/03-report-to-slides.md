# 案例三：把报告做成一份 PPT / Report to Slides

> 需求原话：「把我的报告做成一份 PPT」。

## 世界给了什么

这是四个需求里收获最猛的：两组关键词搜回 **16 条结果、15 个不同流派**——

| 流派 | 代表 |
|---|---|
| Markdown 大纲 → 真 .pptx | `slide-deck-generator`（201⭐）：自动挑版式（标题页/两栏/图文），渲染脚本齐全 |
| AI 配图演示稿 | `deck-generator`（2563⭐ 仓库，自带 4 个转载拷贝的族） |
| Word 文档直转 PPT | `doc2deck`：.docx 进，.pptx 出——"报告变 PPT"的字面解 |
| 带品牌模板的 | 营销内容套企业模板出片的也有 |

接通的是 `slide-deck-generator`：6 个文件（含渲染脚本、示例大纲、依赖清单）。

**安检环节出了个好教材**：6 处命中——逐条人审后发现全是 README 里的本地示例命令（`curl http://localhost:4000/...`）和"怎么装依赖"的说明文字。**命中 ≠ 有问题**，安检是把可疑处摆出来让人看，不是自动枪毙；人审放行，装。

## 启示

1. **越大众的需求，世界给的选择越多**——多到你需要的不是"找"而是"挑"：按自己的输入格式挑（我有 Markdown 还是 Word？要不要 AI 配图？）。
2. 安检的正确用法是人审判读：教人装依赖的 skill 必然命中"pip install"，这恰恰说明它文档齐全。

## 数据来源

- 本篇是众多实际找寻记录里挑出的典型之一。
- 两组关键词跨源搜索 16 条 15 族；入选者 `--dry-run` 全文件安检 + 逐条人审。
